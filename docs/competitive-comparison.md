# Clipboard manager comparison

Accessed 25 September 2026. This short review uses vendor help pages, project repositories, and release notes. It makes no performance measurements. Vendor feature descriptions are identified as such; repository code is implementation evidence for the checked branch and may differ from a released binary.

| Product | Primary-source evidence | What MacClippy can learn |
|---|---|---|
| **Paste** | Vendor documentation describes age-based retention options from one day to forever, pinning and Pinboards, app exclusions, pause, multiple-item paste, and search across content and OCR text. It says exclusions apply to future copies; existing entries must be removed separately. [Retention](https://pasteapp.io/help/control-history-retention), [app exclusions](https://pasteapp.io/help/exclude-apps), [search](https://pasteapp.io/help/search-and-filters), [Mac features](https://pasteapp.io/help/paste-on-mac). | Keep age retention distinct from count and byte budgets. Explain how exclusions affect already-captured history. The reviewed help pages do not establish Paste's item-count or byte limits. |
| **PastePal** | Vendor help describes pausing capture, a manual “Read clipboard” action while paused, app/content/pattern rules, cleanup exceptions, and queue mode. The product page calls search “fast” and indexed; that is a marketing claim, not a benchmark. [Manual tracking](https://docs.indiegoodies.com/pastepal/Mac/features/manual-tracking), [settings](https://docs.indiegoodies.com/pastepal/Mac/features/settings), [cleanup](https://docs.indiegoodies.com/pastepal/Mac/features/history-cleanup), [queue](https://docs.indiegoodies.com/pastepal/Mac/features/queue), [product page](https://indiegoodies.com/pastepal). | State whether deliberate manual capture is available while automatic capture is paused. Document cleanup exceptions and queue ordering. A queue limit is not evidence of bounded history storage. |
| **Maccy** | Its README and current repository code show a configurable polling interval, temporary capture disable, filtering for concealed/transient pasteboard markers, and paste-stack interruption after an external clipboard change. Release notes describe fixes involving plain-text paste, preview-close freezes, and insertion at full capacity. An issue reports a CoreText hang involving U+FFFC, CJK, and emoji; this is useful adversarial test inspiration, not a MacClippy defect report. [README](https://github.com/p0deje/Maccy/blob/master/README.md), [`Clipboard.swift`](https://github.com/p0deje/Maccy/blob/master/Maccy/Clipboard.swift), [2.7.1 release notes](https://github.com/p0deje/Maccy/releases/tag/2.7.1), [issue #1520](https://github.com/p0deje/Maccy/issues/1520). | Keep paste stacks interruptible when the system clipboard changes. Add Unicode regressions for combining marks, CJK, emoji, and object-replacement characters. Release notes and user issues identify cases to test; they do not quantify frequency or performance. |
| **CopyQ** | The project documents text, HTML, images, and custom MIME formats. The v16.0.0 release notes describe per-MIME size limits and OOM protection. The FAQ documents a default per-MIME size limit, item limits, unloaded inactive tabs, and separate-file/lazy payload loading. [README](https://github.com/hluk/CopyQ), [v16.0.0 release](https://github.com/hluk/CopyQ/releases/tag/v16.0.0), [FAQ](https://copyq.readthedocs.io/en/stable/faq.html), [security](https://copyq.readthedocs.io/en/stable/security.html). | Define input and retained-payload bounds before expensive decode, indexing, or OCR. Test full-capacity and file-manager representation round trips. CopyQ's documented values are its own settings, not MacClippy measurements or requirements. |
| **Clipy** | Release 1.3.0 notes describe a Realm-to-SQLiteData migration and warn that migration can fail in some cases, recommending export of important snippets first. Current `develop` source shows configurable capture formats, concealed-content filtering, background OCR, and cancellation-aware cleanup; branch code is not a guarantee about the released app. [1.3.0 release notes](https://github.com/Clipy/Clipy/releases/tag/1.3.0), [`ClipService.swift`](https://github.com/Clipy/Clipy/blob/develop/Clipy/Sources/Services/ClipService.swift). | Exercise restore and upgrade using persisted data, not only fresh stores. Keep background work cancellable and make cleanup behavior explicit. |

## How to read the evidence

- **Architecture/source evidence:** MacClippy's 50/400 ms polling policy is defined in [`MacClippyPasteboardPollPolicy.swift`](../MacClippyKit/Sources/MacClippyPlatform/MacClippyPasteboardPollPolicy.swift), its default item and payload caps are in [`MacClippyStorageCapPolicy.swift`](../MacClippyKit/Sources/MacClippyCore/MacClippyStorageCapPolicy.swift), and CryptoKit AES-GCM plus the Keychain backend are in [`Crypto.swift`](../MacClippyKit/Sources/MacClippyCore/Crypto.swift). These describe implementation choices, not speed or resource measurements.
- **Vendor marketing:** PastePal's product-page search wording is presented as its claim, not as a measured comparison.
- **Initial acceptance targets:** warm-panel p95 ≤100 ms, search at 10k records p95 ≤100 ms, and search at 100k records p95 ≤200 ms. These project targets are not measurements or competitor claims.
- **Actual measurements:** This review collected no MacClippy or competitor benchmark results. The repository's scale fixtures are regression tests, not published comparative measurements.

## MacClippy recommendations

- Keep age, item-count, and byte limits visible as separate controls and explain pinned-item behavior at capacity.
- Preserve clipboard representations and metadata needed for paste. Test rich text, HTML, images, file URLs, multiple files, and custom formats.
- Exercise pause, exclusion, and clear-history behavior while OCR, indexing, cleanup, or queued paste work is in flight.
- Add Unicode search/paste regressions for normalization, combining marks, CJK, emoji, bidi text, long strings, and U+FFFC.
- Measure capture, search, paste, memory, CPU, and UI behavior on named hardware and macOS versions before publishing numeric claims. No competitor or MacClippy performance comparison is made in this document.

The recommendations are test and documentation opportunities inferred from the cited product behavior and source evidence; they do not imply that every listed failure has occurred in MacClippy.
