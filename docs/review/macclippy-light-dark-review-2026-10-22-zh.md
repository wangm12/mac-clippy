# MacClippy 浅色／深色 UI 复查（2026-10-22）

环境：macOS 27.0.1，原生 SwiftUI / AppKit。使用 Release E2E 应用、隔离目录和合成数据；外观覆盖仅作用于测试进程，没有修改 macOS 外观或用户配置。

## 发现并修复

### P2：外观切换后，已有卡片可能残留上一种模式的配色

工具栏已经切换到浅色，部分保留的卡片仍显示深色背景和白色文字。原因是主题在构建 SwiftUI 视图时把 `isDark` 转成了固定 NSColor；复用的卡片无需重新构建，因而保留旧颜色。

主题改为使用按绘制外观解析的动态 NSColor，覆盖卡片、文字、边框、搜索框、弹窗和预览表面。修复后已在面板保持打开、记录保持不变的情况下检查浅色 → 深色 → 浅色，卡片和多选栏同步更新。

### P2：多选主按钮文字对比度不足

原来的亮度判断直接使用未经线性化的 RGB。当前系统蓝色填充上的浅色文字约为 3.71:1。改为根据 sRGB 相对亮度比较黑色与白色文字，选择对比度较高的一种；普通和悬停背景保持不透明，按各自实际填充计算文字颜色。当前系统蓝色下约为 5.23:1。

这是自定义多选主按钮的修复，不代表全应用所有文本均完成 WCAG 合规认证。

## 验证

- 51 项测试通过：ChromeHitTarget、DetailsWorkflow、HeaderRendering、LiquidGlass、PreviewPresentation、Settings。
- 新增保留颜色对象在浅色 → 深色 → 浅色中解析的回归检查，以及多个强调色、两种外观、普通／悬停按钮的 ≥ 4.5:1 检查。
- SwiftLint（现有 baseline）和 `git diff --check` 通过。
- Release E2E 构建通过；正式 Release 另行构建后安装。

扩大测试时，详情测试的轮询曾在复制工作线程读取同一个 NSPasteboard 对象时直接调用 `string(forType:)`，触发 AppKit 类型缓存崩溃。崩溃栈显示两条路径并发访问。测试读取现已使用生产代码相同的访问协调器；修正后 51 项测试整批通过。该改动只修复测试夹具，不改变复制业务逻辑。

## 覆盖边界
